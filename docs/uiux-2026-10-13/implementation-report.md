# UIUX 구현 및 검증

대상은 `ehdgus554/jikkot`, main, 기존 Cloudflare Worker `jikkot`과 `https://jikkot.ehdgus554.workers.dev/`입니다. 첨부 요청서와 screen-audit를 모두 읽고 실제 앱의 인증·API·진행 상태에 연결했습니다. 통합 HTML의 검토 선택기, 회원 체크박스, 예시 계정·기록·인증번호·고정 날짜는 운영 번들에 넣지 않았습니다.

## 구현

공통 Header/Logo/Surface/ChoiceCard/PrimaryButton/ConsentRow/BodySelector/ResultSummary와 기존 RoutineMedia를 사용합니다. 원본 로고·거북이·compact soft sketch, 공식 Google G, LINE Seed KR 400/700 및 Nunito 실제 200~1000 축의 폰트·라이선스를 self-host합니다. 자산 manifest의 22개 파일과 동작 PNG 11개의 원본 바이트를 대조했습니다. 이전 자산은 삭제하지 않았습니다.

홈·자세·5부위·습관·최근 행동·동작·피드백·완료·불편 과정·종료·기록·로그인·가입·가입 완료를 실제 상태로 연결합니다. 비회원/소셜 동의, 인증 준비, 하루 제한, 빈 기록, 대체 없음, 연결 오류/재시도, 준비 메뉴, 실제 요청 중 표시, 동의 거절, 회원 접근 안내, 미지원 자세, 저장 실패도 연결합니다. 승인된 대체 매핑이 나중에 제공되는 경우 동일한 실제 동작 화면을 재사용합니다.

부위는 머리·목·어깨·등·허리뿐이며 추천 질문은 정확히 세 개입니다. 이후 부위는 표시만 하고 뒤로 돌아가서 변경합니다. 변경 시 후속 입력·결과를 초기화하며, 단순 뒤로 가기는 답변을 보존합니다. 자세는 처음 한 번 선택하고 현재 없는 서기/눕기는 준비 상태로 안내합니다. 기존 서비스의 가능한 자세 집합 데이터 및 과거 기록 계약은 변경하지 않고 새 자세 화면에서 실제 선택 자세의 지원 여부를 별도로 확인합니다.

피드백 세 선택은 즉시 전송합니다. 전송 중 ref와 disabled로 중복 요청을 막고, 실제 성공한 뒤 자동 기록/분기로 이동합니다. 동일 추천·submission ID로 응답 유실 후 재시도와 재접속이 가능합니다. 비슷함의 후속 요청 실패도 기존 ID로 재시도합니다. 불편 과정은 승인된 동작의 실제 단계 문구를 사용하며 새로운 임상 대체 매핑을 만들지 않습니다.

과거 MV 및 jikkot11-v1 기록은 원래 부위·동작·피드백 스냅샷으로 보존하고 펼침 상세로 표시합니다. 이전 데이터에 자세가 없으면 정보 없음으로 표시합니다. 비회원 기록을 가입 후 옮기지 않고, 로그아웃/다른 계정에서 이전 계정의 기록·진행 상태가 노출되지 않습니다.

페이지 title, Open Graph title/site_name, Twitter title은 **직꼿**입니다. 공유 이미지와 탭 아이콘도 최종 원본 워드마크를 사용합니다. 내부 npm 버전은 공유 제목과 별개이며 변경하지 않았습니다.

## 대비와 접근성

브랜드 코랄 #EF7564와 인디고 #252A76의 대비는 4.4265:1입니다. 색을 바꾸지 않고 CTA를 굵은 19px로 설정해 큰 글자 AA 기준 3:1을 충족합니다. DOM에서도 실제 크기·굵기를 검증합니다. 보조 글자는 #686774로 밝은 표면에서 5.47:1, soft 표면에서 5.11:1입니다. SVG 키보드 초점은 사각 기본 outline 대신 실제 부위 윤곽의 인디고 선으로 표시합니다. 터치·hover·선택 해제·pointercancel, reduced motion, 16px 입력과 약 44px 이상의 일반 컨트롤을 지원합니다. 글꼴 실패는 안내를 표시합니다.

## 실행 결과

- 콘텐츠 42,544개 조합, 46개 분기, 원문 29개 사례: 통과. 초기 추천의 ID·분기·문구는 보존했습니다.
- 서비스 13개: 통과. 승인된 명시적 대체 매핑 없이는 종료하며, 매핑을 주입한 테스트에서는 패턴/피드백/과정/방문 동작/부위 조건을 검증합니다. 테스트용 매핑은 운영에 활성화하지 않습니다.
- UI 컴포넌트 7개: 통과.
- 이미지/브랜드/폰트·라이선스/대비 13개: 통과.
- 실제 Auth 및 Firestore 에뮬레이터 Spark API·규칙·서명 JWT 검증 10개: 통과.
- 브라우저 125개 고유 시나리오(320/390/768/1024/1440px): 통과. 기존 115개 전체 실행과 신규 Google 동의/폰트 실패 10개 실행을 합산했습니다. 추가 수정 후 관련 화면·재시도도 재검증했습니다.
- Google 신규 가입 동의는 실제 Auth 에뮬레이터의 Google identity 및 서버 활성화 경로를 사용합니다. 운영 Google OAuth 창/실사용자 로그인을 검증했다고 보고하지 않습니다.
- 타입 검사(참고 Functions 포함), ESLint, 콘텐츠 검사, 운영 연결 빌드와 jikkot 대상 guard: 통과.
- local production workerd: 원본 자산 HTTP 200/해시, font MIME/CORS/장기 cache, 원시 SSR title/OG/Twitter, 모바일/데스크톱 portal CTA 스타일·가로 넘침 검증 통과.

현재 머신의 Firebase CLI 기본 Firestore 1.19.8 다운로드가 네트워크에 차단되어 Google의 공식 SDK 배포에서 SHA-256을 검증한 Firestore 1.22.0과 Java 21을 사용했습니다. Auth는 기존 firebase-tools 14.22.0 에뮬레이터입니다. 무결성 검증을 끄거나 기대 체크섬을 변경하지 않았습니다.

시안과 앱을 390/1440px 캡처로 대조했고 모든 화면 크기에서 주요 흐름 캡처를 생성했습니다. 근거는 `outputs/uiux` 및 Playwright 결과의 이미지입니다. 홈의 이미지·설명 순서와 제목 크기를 최종 원본에 맞추고, 어깨 영역의 클릭과 SVG 초점 표시를 수정했습니다.

## 준비 상태로 남긴 사항

현재 실제 인증은 Firebase 이메일·비밀번호와 Google입니다. 아이디 로그인 브리지가 없으므로 이메일을 정보용 필드라고 거짓 표시하거나 새 비밀번호 서버를 만들지 않았습니다. 아이디는 기존 서버의 고유 프로필 필드입니다. 휴대폰 인증과 카카오·네이버는 준비 상태이고 가짜 인증/만료 코드/회원 성공을 사용하지 않습니다. SMS 구매·Blaze·새 프로젝트/도메인·Firebase Functions 배포는 하지 않았습니다.

승인된 pattern/feedback/process 기반 대체 매핑은 아직 없습니다. 부위 전체를 순환하던 이전 구현 대신 ‘추가로 안내할 동작이 없어요’로 마무리합니다. 새 매핑과 서기/눕기 콘텐츠는 소유자가 승인해야 할 콘텐츠 항목입니다.

운영자명 Jikkot, 보유기간 방침 탈퇴 시까지를 반영했습니다. 소유자 요청대로 문의 이메일·확정 약관은 미정이며 `reviewedForLaunch=false`와 draft-v1을 유지합니다. 탈퇴·삭제 절차와 확정 약관은 준비 중임을 표시합니다. 검토됐다고 flag만 변경하지 않았습니다.

## 운영 배포 확인 범위

기존 Git main 연동으로 배포합니다. 현재 실행 프록시는 api.github.com, api.cloudflare.com 및 운영 workers.dev CONNECT를 403으로 차단합니다. 네트워크 권한 요청이 허용됐지만 프록시의 제한은 그대로였습니다. 필요한 도메인과 재현 가능한 개발 설치·시작 지침을 환경 초안에 저장했습니다. 저장은 현재 네트워크 변경이나 운영 배포 성공을 의미하지 않습니다.

이 제한 때문에 Git push만으로 production 성공을 선언하지 않습니다. 운영 Cloudflare의 최신 작업 결과와 실제 사이트는 소유자 확인이 필요한 별도 단계입니다. 커밋/푸시 및 확인 가능한 결과는 `outputs/uiux-deployment.json`에 기록합니다.
