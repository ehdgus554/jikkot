이 변경은 업로드된 `Jikkot_Web_Development_Prompt_2026-10-16.md`와 3개로 나눈 이미지 ZIP을 기준으로 구현했다. 문서의 제품 요구사항은 구현 자료로 사용했고, 배포·콘텐츠 승인 권한으로 간주하지 않았다. 현재 브랜치는 `work`, 작업 시작 기준 커밋은 `8507100`이다.

## 반영한 내용

- 홈의 주요 메뉴를 불편한 곳 풀기 / 운동 전 몸풀기 / 여유롭게 몸풀기로 구성했다. 기존 로그인, 게스트 일일 제한, 승인된 11동작 추천 및 과거 기록을 유지한다.
- 새 흐름은 10개 부위, 앞·뒤 신체 선택 그림, 실제 자세·지지물, 평소 습관과 오늘 상태를 구분한다. 없음·모름·미응답을 구분하고 서버에서도 입력을 검증한다.
- P01–P20 명시 조건, P21 운동별 기본 구성, 8개 운동 종류, 12개 준비운동 조정 항목, 여유 5/10분 구성 후보를 등록했다. 부정 반응은 한 번부터 동작·같은 계열·확인된 부담 방향 제외에 반영한다. 근육 약화나 진단을 추론하지 않는다.
- 묶음의 좋은 느낌을 각 동작의 좋은 반응으로 복사하지 않는다. 실제 완료·넘김·중단·일시정지·재개·후속 느낌을 세션 단위로 저장한다. 삭제/정정은 파생 기억도 다시 계산한다. 새 기록은 20개 단위로 조회한다.
- 세션/이벤트 UUID와 Firestore CAS 트랜잭션으로 생성·피드백 재전송과 동시 요청을 처리한다. 실제 REST의 `FAILED_PRECONDITION` 충돌도 재시도한다. 페이지 새로고침 시 사용자별 진행 상태를 복원한다.
- 검토 권한은 서버의 배포 단계 + 플래그 + 회원 UID 목록을 모두 검사한다. 검토 기억·습관·성장 상태는 일반 이용 자료와 분리한다. 일반 세션 응답에는 추천 판단·제외 이유·부담 방향을 노출하지 않는다.
- AI는 동의와 서버 설정이 있는 경우만 사용할 수 있는 제한된 요약 어댑터다. 시간 초과·잘못된 형식·미동의·미설정은 규칙 방식으로 돌아간다. 실제 유료 AI 호출은 하지 않았다.
- 성장 기능은 서버 플래그와 사용자 선택을 모두 요구한다. 한국시간 월–일 기준 주당 완료 50 + 느낌 10, 최대 60점이다. 후속 느낌·정정·재전송으로 소급 지급하지 않는다. 6개 단계와 3개 배지를 표시한다.

## 원본 이미지와 승인 경계

분할 ZIP은 25 + 25 + 24 = **74장**이다. `public/assets/jikkot74`에 재인코딩 없이 원본 바이트를 설치했다. CSV 관리번호, 코드, 파일명, SHA-256, PNG 크기와 알파 채널을 검사했다. 검증 자료는 `lib/personalization/media-manifest.json`, `docs/jikkot74-csv-mapping.json`이다. 기존 11개 ID는 바꾸지 않았으며 예전 PNG와 과거 매니페스트도 보존했다. 이미지는 자연 비율과 `contain`으로 보여 준다.

**기존 콘텐츠 승인 11개 / 신규 초안 63개 / 새 연결 규칙 승인 0개**다. 기존 동작의 콘텐츠 승인이 새 개인화 연결의 승인까지 뜻하지 않으므로 `approvedConnectionIds`는 비어 있다. 일반 사용자의 불편한 곳 풀기는 기존 승인 엔진으로 연결하고, 새 준비운동·여유 구성은 검토 중으로 표시한다. 검토 회원은 초안 표시와 함께 새 3개 흐름을 확인할 수 있다. 공개 전환은 검토 결과를 근거로 별도 코드 변경으로 수행해야 한다.

74개 모두 원본에 확정된 수행량이 부족하여 임의의 초·횟수를 만들지 않았다. 5/10분은 목표와 구성 분량이며 실제 소요 시간 확정이 아니다. D31은 지지 조건 확인 전 항상 제외한다. 종아리·발목의 동적 추가 후보는 원문 근거가 부족하여 빈 목록이다. 모든 이미지의 임상 적합성·수행량·새 연결·묶음 순서는 내용 검토가 남아 있다.

## 로컬에서 이어서 실행

Node 22와 Java 21이 필요하다. 루트와 `functions`에서 잠금 파일 기준 `npm ci`를 수행한다. 기본 에뮬레이터 설정은 README를 따른다.

```bash
npm run emulators
# 별도 터미널, 실제 로컬 Auth/Firestore가 열린 뒤:
FIREBASE_AUTH_EMULATOR_HOST=127.0.0.1:9099 npx tsx scripts/seed-personalization-review.ts
JIKKOT_REVIEW_UIDS=jikkot-local-reviewer npm run dev:api
# 별도 터미널:
npm run dev -- --port 5173 --strictPort
```

검토 시드는 **로컬 에뮬레이터 전용**이다. `reviewer@example.test` / `LocalReview123!`로 실제 에뮬레이터에 로그인한 뒤 설정에서 검토 흐름을 켠다. 운영 계정이나 비밀정보가 아니다. 일반 회원/게스트에게는 검토 토글이 없다.

대표 확인 순서: 등 + 견갑골을 모으는 습관 + 등 위쪽/앞으로 뻗기 편함 → 새 단일 동작; 불편 반응 뒤 같은 부담 후보 제외; 축구 준비 → 완료/공간 부족 넘김/일시정지/재개/묶음 느낌; 의자 자세 여유 5분 → 직접 완료; 새로고침과 응답 유실 재전송; 타인 세션·비허용 UID의 검토 API 차단; 기록 삭제와 후속 느낌.

## 배포

`npm run build:review`는 기존 `jikkot-review` 대상과 HTTPS API 주소를 고정하고 에뮬레이터·준비 화면 설정을 거절한다. `npm run deploy:preview`는 같은 검사 후 기존 검토 Worker로 배포한다. 운영 `jikkot`으로 자동 승격하지 않는다.

현재 클라우드 머신은 Cloudflare에 로그인되지 않아 원격 배포가 완료되지 않았다. 배포 계정의 인증/권한을 환경 설정에 안전하게 연결해야 한다. 검토 Worker에는 서버 전용 `FIREBASE_SERVICE_ACCOUNT` Secret이 필요하고, `REVIEW_ALLOWED_UIDS`에는 동의한 검토 회원의 Firebase UID를 설정해야 한다. 빈 목록은 모두 거절한다. Google 로그인을 쓰려면 Firebase 승인 도메인에 기존 검토 호스트가 있어야 한다. 키나 토큰을 채팅 또는 `VITE_*`에 넣지 않는다.

대상 주소 `https://jikkot-review.ehdgus554.workers.dev`는 **배포 목표이며 이 변경의 게시 확인 주소가 아니다**. 배포 후 실제 로그인·저장·권한·74장 자산과 모바일 흐름을 다시 확인해야 한다. 개인정보/운영 정책 문구와 기존 탈퇴 운영 절차의 최종 확정도 별도 검토 대상이다.

## 2026-10-17 배포 재개 결과

환경 게시 후 `CLOUDFLARE_API_TOKEN`이 현재 런타임에 연결됐으며 Wrangler 계정 인증에 성공했다. `npm run deploy:preview`의 최종 빌드·대상 검사도 통과했다. 그러나 정적 파일 업로드 요청(`/workers/assets/upload`)이 `Unauthorized: authentication failed for integration codex-secret-api.cloudflare.com`, HTTP 401로 실패해 배포는 완료되지 않았다. Wrangler는 이 단계에 별도 업로드 세션 JWT를 사용한다. 계정 API 토큰 인증 성공과 업로드 프록시 인증 실패를 구분해야 하며, 토큰을 다시 만들면 해결된다고 단정할 수 없다.

배포용 독립 ZIP `outputs/jikkot-review-deployment.zip`을 생성했다. 74개 원본을 포함하는 빌드 결과와 상대 경로 설정, 한국어 실행 안내가 들어 있다. 로컬 경로·네트워크 시크릿 값을 제거했고 비밀 토큰 포함 여부를 검사했다. 분리된 설정으로 Wrangler `--dry-run`이 통과했다. PC에서 압축을 풀고 Node 22 이상으로 다음을 실행하면 이 환경의 프록시를 거치지 않고 본인 Cloudflare 계정의 공식 로그인 경로로 배포할 수 있다.

```bash
npx --yes wrangler@4.92.0 login
npx --yes wrangler@4.92.0 deploy --config dist/server/wrangler.json
```

이 방법의 실제 원격 배포는 아직 실행하지 않았다. 서버 키·검토 UID 설정과 원격 동작 검증도 여전히 필요하다. 새 API 토큰을 채팅이나 파일로 받지 않는다.

## 운영 반영 경로 (2026-10-17)

사용자가 운영 서비스 적용을 명시적으로 요청했다. 기존 GitHub main 커밋의 `Workers Builds: jikkot` 성공 기록과 운영 Worker의 서버 키 바인딩을 확인했다. 현재 머신의 직접 업로드 대신 기존 GitHub main → Cloudflare Workers Builds 연결을 사용한다. 운영용 빌드 대상은 `jikkot`이며 기존 서버 Secret은 유지한다. 신규 초안 콘텐츠의 검토 제한은 운영 배포 승인과 별개로 유지한다. 배포 완료 여부는 새 커밋의 Cloudflare check 결과와 실제 운영 주소의 새 자산·API 응답으로 확인한다.
