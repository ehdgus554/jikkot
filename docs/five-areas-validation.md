# 다섯 부위·세 질문 변경 검증

기준: 사용자가 전달한 [다섯 부위 실행 명세](five-areas-request.md). 대상 저장소는 `ehdgus554/jikkot`, 기존 운영 Worker는 `jikkot`, 기존 주소는 `https://jikkot.ehdgus554.workers.dev/`입니다. 새 사이트·도메인·Firebase 프로젝트·요금제를 만들지 않습니다.

## 실제 호출 경로와 변경

- `app/five-areas-spec.ts`: 원문 SPEC의 다섯 부위, 선택지 문구/순서, 프로필, 합성 조건, 46개 규칙, 허용 동작을 그대로 보관합니다.
- `app/jikkot-data.ts`: 머리/목/어깨/등/허리만 노출합니다. 11개 동작의 안정적인 ID, 단계, 원본 PNG, 시간/횟수 없는 기존 승인 안내는 유지하고 새 부위 매핑만 연결합니다.
- `lib/service/decision-trees.ts`: 바깥 AND/안쪽 OR, 위에서 아래 첫 분기, 이전 분기 제외 조건을 적용합니다. 분기에 실제로 일치한 입력만 수집합니다.
- `lib/service/recommendation.ts`: 버전은 `jikkot11-v2-fiveareas`. 특별 옵션 배타/빈 입력 정규화/프로필 밖 선택 검증/한 동작/실제 입력 이유/같은 부위의 중복 없는 대체 추천을 유지합니다.
- 실제 UI `app/jikkot-app.tsx` → 공개 미리보기 `lib/service/public-preview.ts` → 새 엔진으로 연결됩니다. 회원/비회원 서버 요청 `worker/spark-api.ts` → 동일 엔진/스냅샷으로 연결됩니다. 참고용 `functions/src/index.ts`도 같은 엔진을 가져오며 컴파일을 확인했습니다. Functions는 배포하지 않습니다.
- 질문 제목과 설명은 기존 컴포넌트가 이미 명세와 일치합니다. 첫 질문의 버튼 데이터만 교체하여 세부 위치/네 번째 질문을 추가하지 않았습니다.
- `lib/service/progress.ts`: 소유자·동의가 확인된 이전 `jikkot11-v1` 미완료 세션을 새 첫 질문으로 초기화합니다. 인증 상태나 서버 기록을 지우지 않습니다.
- 과거 `MV009` 및 `jikkot11-v1`의 `front_shoulder` 기록을 원래 부위·제목·피드백으로 표시하는 실제 브라우저 경로를 확인했습니다. 현재 부위 목록으로 과거 기록을 다시 분류하지 않습니다.

Node 22, Java 21, 실제 `demo-jikkot` Auth/Firestore 에뮬레이터, 시스템 Chromium, local Cloudflare workerd로 검증했습니다.

전체 UI 조합 수는 머리 4,160 + 목 1,056 + 어깨 32,896 + 등 4,160 + 허리 272 = 42,544입니다. 빈 배열은 UI 제출의 유효 조합이 아니라 과거 상태 호환 입력이므로 별도 검증합니다.

대표 브라우저 경로는 어깨 한손 작업→4, 물건 밀기→11, 양팔 컴퓨터 작업→7과 머리→10/목→3/등→2/허리→1 기본값입니다. 정적 이미지 전체 표시/모바일 확대, 회원 대체 추천 3→8→7→소진, 기존 동의/하루 한도/기록/로그아웃을 확인했습니다.

## 운영 배포 및 외부 연결의 구분

운영 반영은 기존 main의 Git 연동 Cloudflare Workers Builds로 진행합니다. 완료 후 소스 커밋과 최신 `Workers Builds: jikkot` 성공 결과 및 Worker Version ID를 대조해 최종 응답과 `outputs/five-areas-deployment.json`에 기록합니다. Cloudflare는 완료 체크를 별도 ID로 만들기 때문에 커밋의 최신 체크 목록을 조회합니다.

현재 이 작업 환경의 네트워크 프록시는 운영 `workers.dev` 주소로의 CONNECT 요청을 **403**으로 차단합니다. 허용 범위 밖 실행으로도 같은 결과를 확인했습니다. 그러므로 로컬 workerd의 HTTP/브라우저 검증을 운영 사이트 직접 검증이라고 보고하지 않습니다. 운영 직접 브라우저 확인 및 이미지 200 확인은 현재 접근 제한으로 완료할 수 없습니다. 재현 가능한 검사는 `JIKKOT_SITE_URL=<운영 주소> CHROMIUM_PATH=<Chromium 경로> node scripts/five-areas-production-smoke.mjs`이며 기본 주소는 로컬 workerd 8788입니다.

Firebase 설정이 없는 배포는 문진/추천/완료 공개 미리보기이며 로그인과 서버 저장은 비활성입니다. 사용자 별도 Firebase 앱에서는 로그인이 완료된 화면을 확인했지만, 그 앱의 도구/인증은 현재 Codex 클라우드에 제공되지 않았습니다. 이 환경의 Firebase CLI 로그인 계정은 0개, 프로젝트 설정 조회는 인증 부족으로 실패했습니다. 원격 설정·규칙·인덱스·IAM·서비스 계정 비밀키를 변경하지 않았습니다. 실제 Firebase 연결을 완료했다고 보고하지 않습니다.
